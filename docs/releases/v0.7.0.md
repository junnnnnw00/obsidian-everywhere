# Obsidian Everywhere v0.7.0 — Remote Vault Bridge

Obsidian Everywhere can now serve a local Obsidian vault as graph and semantic
context to MCP clients running on another machine. The notes stay on the
machine you control; the client connects through authenticated Streamable HTTP
over a private network or an HTTPS tunnel.

## What is new

- **Remote Vault Bridge** is now a first-class deployment path for Claude Code,
  Codex, and other Streamable HTTP clients.
- **Local semantic retrieval** and graph context bundles are available remotely,
  alongside the existing full-text, backlink, neighborhood, and path tools.
- **Guarded remote edits** can create, append, move, tag, and reorganize notes.
  Read-only mode remains available and is the recommended starting point.
- **`vault_status`** reports mount state, index freshness, indexed counts, write
  availability, the configured sentinel, and the last full reconciliation.
- **Mount Guard (Beta)** preserves the index and blocks writes if a removable
  drive, NAS share, or container mount disappears. When the vault returns, the
  server verifies it and performs a full reconciliation before reopening writes.
- **English and Korean ngrok tutorials** cover read-only-first setup, stable
  domains, automatic startup, validation, token rotation, troubleshooting, and
  security.
- Static bearer authentication now uses constant-time comparison and failed
  authentication attempts are rate-limited.

## Start here

Try the local sample vault without touching your notes:

```bash
npx -y obsidian-everywhere demo
```

For remote access, follow the
[Remote Vault Bridge with ngrok tutorial](https://github.com/junnnnnw00/obsidian-everywhere/blob/main/docs/ngrok-remote.md).
Start read-only, verify the remote vault identity and note counts, then enable
writes only if you need them.

## Beta feedback wanted

Mount Guard remains Beta because removable drives, NAS shares, and container
mounts behave differently across operating systems. We are looking for five
people willing to test a real remote-vault setup and report what is clear,
fragile, or missing. No vault contents need to be shared.

See the beta tester issue in the repository to join.

## Security notes

The bearer HTTP server does not provide TLS by itself. Use it only behind a
private network or an HTTPS-terminating tunnel, use a long unique token, and
never commit the token or tunnel credentials. Public OAuth connectors keep
write tools disabled unless explicitly enabled.
